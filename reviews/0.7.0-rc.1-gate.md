## BLOCKER (1)

### B1 — The barrel exports 13 bare common nouns from `carve`, and `box` now means two different things

`src/index.ts:496-511` · lenses: dryness / dx / ecosystem / blast-radius (4 findings, deduped)

`src/index.ts:323-330` carries the rule verbatim — _"These are COMMON NOUNS (box, table, button, edit, insert…); exporting them bare from a library barrel collides with every consumer's own vocabulary, so the family lives in one container… Decided at the 0.6.0 rc gate"_ — and `box` from `./box` is imported at :333 **only** to be hidden inside `ui`. Line 502 then re-exports a _different_ `box` (an SDF rounded-box carve) at top level, alongside `sphere`, `capsule`, `tube`, `union`, `smoothUnion`, `subtract`, `intersect`, `roughen`, `warp`, `shaft`, `flange`, `applyCarve`, plus `gulley`/`cover` from landform and `terrainDensity`/`composePatches`/`circleFootprint`/`marginBlend`/`latticeHash`/`latticePoint`/`extractChunk` — 20 new permanently-public symbols.

Verified consumer symptom (type probe against the real barrel):

```
error TS2322: Type '(centre: Vec3Like, half: Vec3Like, rounding?: number) => Carve' ...   // box
error TS2322: Type '(opts: BoxOptions, ...children: BoxChild[]) => Box' ...                // ui.box
```

TS catches it, but the message gives no hint that two `box`es exist. And this is the _taught_ API: the `b3d-patch` doc demo (`src/b3d-patch.ts:39`) instructs `import { applyCarve, sphere, tube, smoothUnion, roughen, warp, gulley, cover } from 'tosijs-3d'`.

**Why blocker rather than major:** `UI-DESIGN-NOTES.md:659-670` records the identical call at the 0.6.0 gate with the load-bearing reason — _"The rc window made the rename free; after final it would have been a breaking change."_ HEAD is `v0.7.0-rc.1` and 0.7.0 is not on npm, so the window is open. It also attaches this vocabulary to a feature the release itself says not to build on (`b3d-patch`: _"⚠️ EXPERIMENTAL … Don't rely on this component"_), and TODO.md expects the entrance work to redesign exactly this surface.

**Fix (mechanical, ~15 min):** mirror `ui.*` — `export const carve = { sphere, capsule, tube, box, union, smoothUnion, subtract, intersect, roughen, warp, shaft, flange, applyCarve }`, keep `Carve`/`NoiseOptions`/`PatchField`/`Footprint` top-level, and update the `b3d-patch` and `carve` doc demos' import lines. Same treatment for `gulley`/`cover` (note: `pad` and `volcano` were already bare at v0.6.2 — worth folding in, not a regression).

### Terrain / patch subsystem

**M6 — Patch residency is an unhysteretic hard threshold: crossing it disposes every chunk mesh in one frame and re-extracts the whole patch** · `src/b3d-patch.ts:449`, `src/terrain-grid.ts:505`
`patchResident` is a bare step function with no dead band. Measured against the demo's real bounds/carve/landform: **2112 chunks, 8.9 ms probe pass, 0.69 ms/chunk extract, ~612 ms of budgeted rebuild, ~306 synchronous `Mesh.dispose()` in one frame** — i.e. ~150 frames (~2.5 s) at `buildMs: 4` per true edge. Nothing is memoised across the toggle (`_releaseChunks` clears `_chunks`, which holds the `null` miss-memo). The demo itself invites the trigger ("fly around until you spot a hole"). The project treats hysteresis as required elsewhere (`b3d-aircraft.ts:404`, `b3d-clouds.ts:719` _"hysteresis band that stops any boundary thrash"_), so this is a divergence from its own convention.
→ Hysteresis band (enter/exit radius pair), keep the miss-memo across a release, budget `_releaseChunks` like `_extractSome`. _(The finding's `_pending.shift()` O(n) sub-claim is noise — measured 0.06 ms total; drop it.)_

**M7 — Patch residency is encoded 3-4 times, and one copy has a coordinate-frame bug** · `src/b3d-terrain.ts:987-999`, `src/b3d-patch.ts:430-437`
`buildConfig()` returns a `QuadtreeConfig` then re-types five of its own fields verbatim inside its `refine` filter; `b3d-patch._update` builds a third with `maxReach = coarsestTileSize()*4` vs terrain's `coarsestTileSize()*(splitFactor+1.5)` — **560 vs 640 at stock defaults**, unbounded divergence with an explicit `reach`. When the patch's `level` nears `lodLevels-1`, `naturalLevel` saturates and `maxReach` becomes the only discriminator, so the two systems can straddle it: the patch keeps punching `patchMask` holes into tiles terrain has stopped refining. Additionally the duplicated call at terrain :987-991 passes **logical** patch coords against **render-space** `camX/camZ`, while `b3d-patch.ts:439-440` correctly rebases — an error that grows without bound under floating origin. `buildConfig` is `private` and terrain exposes no accessor, so the copy is structural.
→ Hoist the literal and expose one public `isPatchResident(cx, cz, level)` on `B3dTerrain`; delete the patch's reconstruction of terrain LOD maths from `(terrain as any)`.

**M8 — b3d-terrain's Attributes table states three wrong defaults, and the entire new terrain surface is absent from the page** · `src/b3d-terrain.ts:220-226`
Table says `grossScale 0.1`, `detailScale 0.5`, `detailAmplitude 2`; actual defaults changed this release to `0.015`, `0.09`, `3` — 6.7× and 5.6× off in frequency, i.e. the page documents precisely the values the commit set out to abolish ("homogenous pudding"). Already published in `docs/b3d-terrain/index.html`. Missing entirely from the page: `biomeLapseRate`, `patchMask`, `patches`, `heightSampler()`, `rimCollar`, the `worldV` 0→0.25 change — plus `normalSmoothing`, `center`, `biome`, `biomeSeaLevel` (the page's own demo uses `center: true`, an attribute the reader can't find). A consumer cannot wire a `b3dPatch` without these.
_Adjacent, out of scope for this finding but worth a look:_ `recenter()` at :1471-1473 sets `worldV = 0`, putting the world back on the mirror plane the new 0.25 default exists to avoid.

### Coverage

**M10 — The GLSL gained a whole new classification axis (`interior`/`waterTable`/`noWater`) with zero tests, and the pure mirror `biome-chart.ts` was not updated** · `src/biome-plugin.ts:675`
The shader now decides submersion by `flooded = noWater<0.5 && wp.y < waterTable` when `interior>0.5`, ramps cliff from the per-vertex channel on interiors, and splits `provVolc` from `provLocal` specifically to stop a cave mouth shading as a volcano (the comment records the regression: _"black basalt and glowing lava inside an ordinary cave"_). `biome-chart.ts`/`.test.ts` are byte-for-byte unchanged and contain none of these names — yet `mantaAxes` literally contains `const underwater = altitude < 0`, the expression the shader replaced. The plugin's own doc calls itself _"the GLSL mirror of biome-chart's pure, unit-tested model — one function per shader expression, same names"_. Fragility is demonstrated, not hypothetical: four consecutive fix commits on this block, one of which shipped a **fragment shader that would not compile** (`21b533ba`) with the suite green throughout.
→ Mirror the three params into the chart classifier and pin: interior floor → rock; interior below `waterTable` → submerged while its mouth above shore is not; `noWater` → dry at any depth; and with `interior` set, the province channel never drives volcanism (the exact regression, failing-first).

**M11 — Two new stateful models in b3d-aircraft are inline and untested — and one has a confirmed logic inconsistency** · `src/b3d-aircraft.ts:907,1263,1302`
~130 lines of new frame-stepped math (look-camera spring-back; gear hysteresis + altitude scrub) live only inside `_update`/`_updateGear`/`_scrubGear`; `grep 'gear\|lookX\|lookYaw' src/*.test.ts` returns nothing relevant. The same release extended `fly-by-wire.test.ts` by 276 lines for the throttle model, so this is an internal inconsistency, not an absent convention. **Confirmed defect inside it:** `_inCavity` is set at :846 and the regime path forces `heightAboveGround = +Infinity` in a cavity (:659) while `updatePullUp` early-returns — but `_updateGear(groundDist)` at :896 consumes the raw ray distance. Flying the bore at ~2.5 m AGL drops the gear (`down = gearAltitude*0.6 = 24`), and climbing out past 40 m retracts it. This is a live path: `b3d-patch.ts:136` flies the `scout` (three gear groups) into the bore with `autoGear` defaulting on. Cosmetic today (gear feeds no aerodynamics), but the cavity work should have swept it.
→ Extract `lookStep(state, lx, ly, cfg, dt)` and `gearStep(state, agl, cfg, dt)` into a pure module and pin: clamp at ±`lookRange` / ±`lookRange/2`; frame-rate independence (one dt=1/30 == two dt=1/60); the 0.08 deadzone; the 60 % band under ±AGL noise; interrupted-cycle reversal; and gear honouring the cavity rule.

### Consumer surface

**M13 — The glass gamepad now hides itself on any mouse input by default — undocumented, un-changelogged, and it breaks its own live demo on desktop** · `src/glass-gamepad.ts:320-356,409` _(2 findings deduped)_
New `idleSeconds: 10` / `fadedOpacity: 0` plus an unconditional `_watchRealInput()` (window `keydown`/`pointermove`/`pointerdown` + a 500 ms `getGamepads()` poll) drive `opacity: 0` on the first non-touch pointer event.
