## Blockers

### B1 — `tableRows` abandons a whole doc when the FIRST table's header contains a backtick; all three lamp elements ship 55 attributes with no default and no description
`bin/attribute-index.ts:129` — **confirmed**

`tableRows` locates the *first* markdown header row in a doc comment and, if that header contains any backticked span, `return out` — abandoning the entire document. `src/b3d-lamp.ts`'s first table is the capability matrix at line 186 (`| | shadows | gel (\`projectionTexture\`) | geometry |`), so the genuine `| Attribute | Default | Description |` table at line 298 is never read.

Reproduced in the committed artifact: `static/attributes.txt:343-405` lists `intensity`, `range`, `shadows`, `angle`, `innerAngle`, `gel`, `gelSvg`, `width`, `height` … as bare names for `<tosi-b3d-point-light>`, `<tosi-b3d-spot-light>` and `<tosi-b3d-area-light>` — no `=` default, no prose — where at base each carried its full row. Greppability is measurably worse: `grep -c spot static/attributes.txt` is **3** at HEAD vs **12** at base, so the spot-only attributes no longer surface at all. An agent greps `gelSvg`, finds a bare name, and cannot learn it is spot-only. This is verbatim the outcome the generator's own comment exists to prevent ("A name with no description is the thing this index exists to stop shipping").

Blast radius is exactly one collateral doc: running the guard's logic over every `/*# */` comment in `src/` trips only `touch-gamepad.ts` (the intended target, has no attribute table, loses nothing) and `b3d-lamp.ts`. The three new invariant tests assert names only, so nothing catches prose loss.

**Fix:** scope the header-backtick rejection to the table it heads, not the document — split the doc into tables (header + separator + contiguous `|` rows), drop only tables whose own header cell names an identifier, harvest the rest. Add a golden assertion that `tosi-b3d-spot-light`'s `gel`/`gelSvg`/`angle` carry descriptions. **Re-review scope:** correctness over the remediation diff, plus a re-diff of `static/attributes.txt` and `static/attributes.json` for any other doc whose first table is not the attribute table.

### B2 — `operable` and `debugState` evaluate every veto with `distance: Infinity`, so the documented reach veto reports "blocked" permanently
`src/interactive-behavior.ts:163` (`_apiInfo`, 199-206) — **confirmed, reproduced live**

`_apiInfo()` places `distance: Infinity` after `...this._last` and is shared by `activate()`, `operable` and `debugState`. Driving a real pointer press (hover → down → up at distance 1.2) through `scene.onPointerObservable` on a behaviour carrying the reach veto documented verbatim at `src/b3d-interactive.ts:173` gives `fired=1 refused=0`, `hovered: true`, **`operable: false`**, **`debugState.vetoes: ["out-of-reach:blocks"]`**, `activate(): false` — the pointer path opens the thing at the same instant the public getter and the headset-only diagnostic both say it is blocked. `interactive-veto.test.ts:106` pins that behaviour.

`B3dInteractive.operable` (`src/b3d-interactive.ts:288`) is public API documented as "True when nothing refuses an activation — i.e. using it would do something"; it now says the opposite of what a pointer does. Costs: a consumer gating a "press E" prompt or a highlight on `el.operable` never shows it for any reach-vetoed door; an author running `hj eval $0.debugState` — which this repo treats as the only debug readout available in a headset — reads `out-of-reach:blocks` on a working interactive. Pre-diff the getter used `this._last`, so after a hover it at least reflected the real distance.

Corroborating and unfixed: the doc example `use.activate({ actor: npc })` at `b3d-interactive.ts:183` is now refused by the reach-veto example ten lines above it.

**Fix:** keep `activate()` failing closed on an unknown distance (that part is right and well tested), but give the two *inspection* surfaces the information they have — `this.hovered ? { ...this._last, source: 'pointer' } : this._apiInfo()` — or make `operable` take an optional `info` and re-document both docstrings as "a bare `activate()` with no distance would fire". Either way, have `debugState` print the info it judged with.
