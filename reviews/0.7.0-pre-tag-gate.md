## Blockers

### B1 — `bun run typecheck` is RED at the release commit
`src/model-transform.test.ts:449` — `canonicalize(clone as never)` passes 1 of 3 required arguments.

```
$ bunx tsc -p tsconfig.json --noEmit   # exit 2
src/model-transform.test.ts(449,5): error TS2554: Expected 3 arguments, but got 1.
```

Reproduced independently; it is the **only** error repo-wide. Invisible to every other gate: `bun test` strips types, and `tsconfig.build.json` excludes `src/**/*.test.ts` — precisely the blind spot RELEASING.md:87-91 memorialises ("went red and stayed red across a tagged rc in 0.7.0, hiding four real errors, because the only typecheck anyone ran was the build's"). **Second cycle in a row this gate has been missed.** Introduced by `249587a7`.

At runtime the call survives only by accident: `new BABYLON.TransformNode(undefined, undefined)` falls back to `EngineStore.LastCreatedScene`, which happens to be the probe scene created two lines earlier.

**Fix:** `canonicalize(clone, clone.getScene(), 'cog-probe')` and drop the `as never` casts — those casts are what let an arity error through. Re-run `bun run typecheck` to exit 0 before tagging. *(While there: the test applies `applyCenterOfGravity` to the content node, whereas production applies it to `canonicalize`'s returned wrapper — worth aligning so the regression test exercises the node production actually pivots.)*

### B2 — A live TLS private key is committed and would go public on the release push
`tls/key.pem.bak` + `tls/certificate.pem.bak`, added by `7ce5014d` — the same commit that documented the headset mkcert recipe that creates them.

Verified: both are tracked in HEAD; `head -1 tls/key.pem.bak` is `-----BEGIN PRIVATE KEY-----`; `openssl` parses a real 2048-bit RSA key whose public half matches the committed cert (mkcert leaf for `localhost`, `tosi.local`, `127.0.0.1`, `::1`, valid to **2028-11-21**). `git check-ignore tls/key.pem.bak` → **not ignored**: `.gitignore:176-177` covers `tls/*.pem` and `tls/*.csr`, and `*.pem.bak` matches neither, so `git add -A -- ':!docs' ':!dist'` swept it in.

The repo is public and `origin/main` is 49 commits behind — **the key has not been published yet.** The release push is the event that makes it permanent. Blast radius is narrow (a leaf key, not the root CA; only devices trusting Tonio's mkcert CA, i.e. the Mac and the Quest — and npm is unaffected, `files` excludes it), but a private key entering permanent public history as a side effect of a release push is the archetypal release gate, and GitHub push protection may hard-block the push anyway.

**Fix, in this order:** rewrite the two blobs out of `7ce5014d..HEAD` (one added-commit, cheap while unpushed) — a plain `git rm` leaves the key in the commits you are about to publish. Then widen the ignore to an **allowlist** (`tls/*` with `!tls/.gitkeep`), not another suffix. Then regenerate the dev cert. Then fix the recipe at `CLAUDE.md:205` so it never mints a second copy: `mkcert -cert-file tls/certificate.pem -key-file tls/key.pem localhost 127.0.0.1 ::1 tosi.local <ip>`.

### Correctness (majors)
- [ ] **`openPopup` registers the popup AFTER its mount callback, so a runtime-opened `modal: true` popup blocks nothing.** `popup-surface.ts`: `applyModalBlocking(owner)` runs at :566 (synchronously, via `appendChild` → `whenReady` → `sceneReady`) while `list.unshift(api)` is at :693 — verified by inspection. The modal reads a list that lacks itself, finds `modal == null`, and sets every *other* popup back to `isPickable = true`. Only appears to work in the doc demo, which opens inside `sceneCreated` while the ready-queue is still deferred. Fix: unshift before `appendChild`. Add a test opening a modal against an already-ready owner.
- [ ] **`freeze()` does not stop `B3dControllable`s** — `b3d-controllable.ts:107` bails on `owner.paused` only, never `owner.frozen`, while the frozen branch deliberately keeps calling `scene.render()`. With `reseatFreeze` default on, pressing Re-seat in VR stops terrain/water/projectiles while your aircraft carries on at cruise on its own `Date.now` clock — it can fly into the ground while the modal prompt is up. Same halt-don't-zero-the-stick early return, one extra condition.
- [ ] **`submersible` only filters the ground ray** — `b3d-aircraft.ts:906`'s impact sweep has no water clause, so any hit above `crashSpeed` (default 8) explodes at the waterline. Worse than reported: the dive demo's derived `climbRate` is `maxSpeed * 0.3` = **9 m/s**, so even a full-trigger pure-vertical descent crashes. Surfacing fails identically (Babylon picking does not backface-cull). Factor one predicate shared by `raycastGround` and the sweep so they cannot diverge again.
- [ ] **UI-mesh exclusion is a copy-pasted clause, not a shared predicate.** `isNoCollide` has exactly two call sites, both in `b3d-aircraft`. The launcher's swept ray (`b3d-launcher.ts:527`) and the warhead's `hasLos` (`b3d-warhead.ts:248`) were not updated, so a world-anchored panel stops shells and acts as blast cover. Aggravated: a custom predicate makes Babylon skip its built-in `isPickable`/`isEnabled` filter, so the panel blocks even at `visibility = 0` — and `frame-panel.ts:333` hides gaze-revealed panels exactly that way, i.e. an unrevealed XR panel is an invisible bullet shield. Export one `collidable(own?, extra?)` factory from `b3d-utils` and use it at all the pick sites. *(Known and deferred — TODO.md:35-40 and COLLISION-DESIGN.md:117 already name it; `b3d-biped`/`b3d-car`/`b3d-collisions` gate on `checkCollisions` and are safe.)*
- [ ] **`bringToFront` mixes a frame-stale `mesh.position` with an already-updated `stackLift`.** Two restacks in one frame — the normal title-bar press path (POINTERDOWN handler, then `onDragStartObservable` via a microtask, with no render between) — leave the popup one whole `DEPTH_STEP` short and **permanently** corrupt the `mesh.position − stackLift === base` invariant. The `tearOff` variant is worse: the queued `afterMount` overwrites x/y/z with the world pose and the popup gets no lift at all. Fix: track an un-lifted `basePos` and compute `base + lift` rather than reading back `mesh.position`; convert `toward` into parent-local space for owned popups.

### Efficiency
- [ ] **`openPopup` gives no way to slow the SVG re-serialization.** It builds its plane without `updateInterval`, inheriting the 30ms default, so `SvgTexture.render()` does a deep `cloneNode(true)` + full `XMLSerializer` **before** the `_lastXml` early-out, ~33×/s forever, per open surface. Measured: 0.5 ms/serialize at 300 nodes (a `surface`/`table` panel) on an M-series Mac — several× that on a Quest. And there is no escape hatch: `appendChild` happens inside `openPopup`, so the texture is already constructed by the time the caller holds `.plane`. Add `updateInterval?` to `PopupSurfaceOptions`, default 200–400ms to match the scene panel and frame-panel. *(Note: popups do NOT pay the rasterize/`texImage2D` cost — the dirty-check predates this release — so this is the cheaper half of what those throttles fixed.)*
- [ ] `demoSun` hard-wires `shadowTextureSize: 2048` (doubled this release), overriding the auto device-tier budget for all 14 demos including on a headset — 4× the shadow VRAM and rasterization on the lowest tier. Drop it to the `0` auto sentinel and rely on the new `shadowNormalBias`. **(unverified)**
- [ ] `B3dAircraft.originWorld()` allocates a Vector3 and forces a world-matrix recompute twice per frame on a path documented as allocation-free. Use a `_originTmp` + `TransformCoordinatesToRef`. **(unverified)**
- [ ] `impactMarker` builds two meshes + a material + an observable per impact; the collisions demo can drive ~30/s. Pool the geometry. **(unverified)**
- [ ] `el.make.*` registers every mesh into `B3d.pastAdditions`, which is never pruned — a spawner-facing API feeding a permanently-growing list of strong refs to disposed meshes, each with its own `StandardMaterial`. Compact disposed entries on replay; consider a `material` option in `MakeOptions`. **(unverified)**
- [ ] `B3dLibrary.make` mints a fresh Proxy on every property access (and its `has`/`ownKeys` traps call `getNames()` each probe), unlike `B3d.make` which caches. **(unverified)**
