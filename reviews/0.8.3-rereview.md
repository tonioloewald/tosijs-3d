## Minor

1. **Cloud deck state survives `sceneDispose`: the `_weatherKey` memo and the new `_terrain` cache** (`src/b3d-cloud-deck.ts:1021`, `:1029`; `sceneDispose` ~2369–2394). **Verified (confirmed).**
   - **(a) Stale weather after a re-parent.** `sceneDispose` never resets `_weatherKey`. A re-parent calls `sceneReady` again, which builds fresh meshes with an unbaked colour channel. If the camera snap, `orographic`, `orographicPeak`, `weather` and `generationKey` have not changed, the `_bakeWeather()` inside `_sync()` returns early. The orographic or custom weather field then disappears until one of those inputs changes. The bug predates this diff, but the diff rewrote this exact memo. It is the same bug class as the 0.8.3 terrain B1.
   - **(b) Deck keeps reading the old terrain after a move.** `_terrain` is new in this diff and is also not cleared. A deck moved to a different `<tosi-b3d>` keeps sampling the OLD scene's terrain, as long as that terrain is still connected. Before this diff, the deck queried `this.owner` every time. This part is a narrow regression.
   - Fix: in `sceneDispose`, set `this._terrain = null` and reset the memo from a fresh-memo factory, the same way terrain's `freshBiomeMemo` does. Add a dispose + `sceneReady` test like the terrain B1 test.
2. **Test gaps for the deck rewrite and the direct-params-write guard** (`src/terrain-regenerate.test.ts:483`). _(unverified)_
   - The test "a direct params write survives another dial moving" reportedly passes on the pre-fix code. Its `biomeTemperature` stays at -1, so the per-dial memo is never exercised. Going back to a single joined climate key would stay green.
   - Nothing tests the cloud deck's compare-before-build step, `weather` identity keying, or the cached terrain lookup.

## Nits

3. **Deck re-bakes an all-zero field when it has no field** (`src/b3d-cloud-deck.ts:1580`). _(unverified)_ The default deck (orographic 0, no `weather`) now re-bakes zeros on every 220 m snap and on every terrain rebuild. During a slider drag that means once per rAF. The old key was `'none'` and baked once. This works against the rewrite's own goal of doing less per frame.
4. **Stale comment in `_syncBiome`** (`src/b3d-terrain.ts:1989`). _(unverified)_ It still says "Negative = leave the plugin's own value alone", which contradicts the code just below it. A maintainer who believes the comment could undo B1.
