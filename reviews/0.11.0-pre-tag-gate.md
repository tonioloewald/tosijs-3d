## Follow-ups (minors and nits)

### Board (virta; `TODO.md` is only a pointer), from the correctness, efficiency and docs lenses

**Correctness**
- [ ] **Effect voice budget thrash** (`src/effect-player.ts:615`, verified minor). An evicted voice is rebuilt on the next frame and evicted again. The skeptic corrected the mechanism: the rebuilt voice is not evicted because it starts at `audible = 0`. It keeps the same `audible` value that made it the quietest, so the sort evicts it again. On a 6-voice low or XR tier this leaves about 36 live WebAudio graphs, each with an HRTF panner, per excess voice, and a `url` layer starts a fetch every frame until its buffer decodes. Fix: mark the voice evicted on its runtime, and restart it only when the layer goes off and on again or when it would outrank the current quietest. Add a test with a stub `startVoice` asserting there are no per-frame restarts over budget.
- [ ] **B3dEffect builds its player twice on mount** (`src/b3d-effect.ts:117`, *unverified*, minor). `render()` already calls `_start()`, then `sceneReady` calls it again. For the first effect in a scene, this tears down and rebuilds the shared pool, and it adds an `onDisposeObservable.addOnce` observer each time the pool is recreated. Verify, then drop the explicit `_start()` or make `_start()` idempotent on `_key() === _playing`. Remove the dispose observer in `releaseSceneEffects`.
- [ ] **The water-not-ready debug report can fire falsely in a throttled or hidden tab** (`src/b3d-water.ts:376`, *unverified*, minor). Add `document.visibilityState`, the frames rendered since `sceneReady`, and whether XR is active to the report, or start the 8 s clock only after N frames have rendered.
- [ ] **Sprint/run hysteresis has no test** (`src/b3d-biped.ts:3156`, *unverified*, nit). Extract `(speed, wasSprinting, hasSprint) → state` as a pure function and test enter, hold, leave, and a rig with no sprint clip.

## Completeness gaps
- **Diff basis:** v0.10.7...HEAD spans 12 tagged patches (0.10.8–0.10.19; 0.10.19 is tagged but not on npm, where latest is 0.10.18). Only 4 commits are new since v0.10.19. The raw diff is mostly `docs/` and `dist/` churn; the source-only diff is 126 files and about 18.6k lines.
- **Dirty tree:** the 1327 dirty entries are all in `docs/` and `dist/`. Anything that read `dist/` saw a half-rebuilt state. Stop the server and run a clean build before packing.
- **Shadows (#3420) was not reviewed.** A shadow generator made after the scene is up draws nothing. `src/b3d-shadows.ts` is untouched in this range, so no lens looked at it. This is probably a general bug for late suns or casters, including hosted `mountRigTool`/`mountEffectTool` scenes, and it is the user's stated next task. The rig-tool change works around it rather than fixing it.
- **RELEASING 5a** (a human drives every demo, flat and in VR) has no evidence yet, and it is mandatory for a minor. The new flat and VR surfaces need it: barMenu/viewMenu, the orthographic inspectView with `viewSpanAt`, system-bar panels, and effect audio gesture-gating in a session.
- **Behaviour changes need migration notes:** the retargeting change to hips, spine, neck and head alignment, and the sprint clip. Both are folded into the CHANGELOG follow-up above.
- **Peer range vs dev dependency:** the peer range is `tosijs ^1.9.2`, but dev and tests run on 1.10.7 (tosijs-ui ^1.16.28). Nobody verified that the new code works on tosijs 1.9.x.
- **Public API names were not audited** (no dx or idiom lens). The barrel grew by about 159 lines. Unchecked: the handleX/whenX callback rules, bare common nouns leaking from the barrel, `Deg` suffixes (yawDeg, pitchDeg, armSpaceDeg), and default-true booleans. A minor is where these names get frozen.
- **Core blast radius:** `tosi-b3d.ts` (about +727 lines) and `frame-panel.ts` (about +296) changed. The deferred-teardown and move-not-remove guarantees were not re-checked against the new mount and unmount host-scene paths.
- **Coverage of the Babylon halves** (no coverage lens): effect-player pooling and release, effect-audio, retarget-babylon, rig-build handedness, spring-chain-babylon and seam-material have no unit tests. That is where this cycle's bugs came from.
