## Fix before the tag

Each item below lists the check that shows it is fixed. None of them needs another review.

- [ ] **A press on a settings popup closes the in-scene settings panel.** `src/b3d-svg-plane.ts:1043` (with `tosi-b3d.ts:5903-5922` and `frame-panel.ts:126/894`). Verified. Popups are `B3dSvgPlane`s in the ui layer, and their pointer observer never adds the event to `claimed`. So the host's background-press listener sees an unclaimed press and calls `_closeScenePanel()`. In the default mode, this makes every popup opened from the settings panel unusable.
  - **Fix:** export a `claimPointer(e)` from `frame-panel.ts` next to `pointerClaimedByPanel`. Call it from `B3dSvgPlane`'s `down` handler at the same point where frame-panel calls `claimed.add`. Keep a single WeakSet; do not add a second one.
  - **Check:** add a test, or an emulator script, that opens the flat settings panel, opens a popup from it and presses the popup. Assert the settings panel is still open. The test must fail when the `claimPointer` call is reverted.
- [ ] **A modal re-presented as null across an XR transition is silently dropped: the respawn panel vanishes.** `src/tosi-b3d.ts:1627` (`_representModals`) and `_presentModal`. Verified for scenario (a). The scenario: `flat-ui="dom"`, die in a headset, then exit VR. Re-presenting the modal returns null, but the entry stays in `_modals`. `B3dDeath._modal` is still set, so death never falls back to its world plane. The player is stuck dead with no Respawn button, and the gamepad stays hidden. Scenario (b), a custom `setupXr`, was refuted as described: the observer is never installed in that case. The related problem there, a flat modal left on the flat camera's face frame, is a separate minor below.
  - **Fix:** never leave a `_modals` entry with `close === null`. Two options:
    - Give `showModal` a `fallback()` that the owner supplies (death uses its world plane, pause uses its DOM host).
    - Apply `flatUi` only when a modal is first opened flat, and not when it is re-presented.
  - **Check:** a test that opens a modal with `flatUi='dom'` while `xrActive`, simulates NOT_IN_XR, and asserts that the modal is drawn or its fallback ran. Driving it by hand also clears it: `bun run xr` with death in session, then exit, and the Respawn UI must be visible.
- [ ] **The new `flatUi='scene'` default ships in a patch with no "Changed" note.** `src/tosi-b3d.ts:2298` (`_sceneToolbarSpec`) and `src/scene-toolbar.ts:60/135`. Verified. The HTML toolbar, settings panel and pause are hidden. The in-scene toolbar reads only the `hidden` attribute, so styling with `::part(enterVrButton|scenePanelGear|sceneToolbar)` no longer applies. The source itself expects consumers to use that styling (`tosi-b3d.ts` ~1089). The toolbar now has a third, full-screen button and covers about 150×56 px at the top left. The repo's own examples had to move to `{left: 8, top: 64}`. The CHANGELOG lists all of this only under Added. One overstatement in the finding: the part names appear in a source comment, not on a doc page.
  - **Fix:** add a 0.10.7 "Changed" entry. It should say three things: the HTML corner controls, settings panel and pause are hidden by default, so `::part` styling of them no longer applies; the corner toolbar now covers about 150×56 px; and `flat-ui="dom"` restores the old behaviour.
  - **Optional, preferred:** have `sceneToolbar` skip buttons that are not visible (`getComputedStyle(b).display === 'none'` / `checkVisibility()`), so a consumer's `::part` hide carries over.
  - **Check:** the CHANGELOG entry is present. If the computed-visibility change is made, add a scene-toolbar test that a button hidden with `display:none` is not drawn and is drawn again once un-hidden. The test must fail with the change reverted.

## Verify or fix (unverified major)

- [ ] **(unverified)** **All modals are placed at one pose (screen centre, distance 1, same layer), so two open modals sit coplanar and z-fight.** `src/tosi-b3d.ts:1680`. The lens says it measured this in headless Chrome: pause plus a second `showModal` gave both placement planes the same position and scale. The suggested path is death in a headset, exit VR, and `pause('xr')`. Hiding the tab while dead does the same through `pause('hidden')`. This finding was not checked by a skeptic.
  - **Fix:** stack modals in `_presentModal`, so each newer modal gets a nearer `screenAnchor.distance` and XR distance (the settings panel already uses 0.9). Alternatively, hide older modals while a newer one is open.
  - **Check:** a test with two concurrent `showModal` calls that asserts distinct depths, or that only one is visible.

## Follow-ups, grouped by destination

### This repo: file to the virta board (`TODO.md` is only a pointer)

- [ ] **minor**: `pickLayersFirst` overrides `scene.pickWithRay` during the XR-frame window and ignores the caller's predicate. Its disposer can also remove a wrapper someone installs later. `src/tosi-b3d.ts:643-671`. Verified, and merged from the correctness and blast-radius findings.
  - The window runs from `onXRFrameObservable` to `onBeforeRender`. It covers consumer XR-frame observers, `runRenderLoop`, `onBeforeAnimations` and actions, plus our own re-picks: `tosi-b3d.ts:6571`, `popup-surface.ts:536`, and `b3d-svg-plane.ts:602/714`, depending on the order observers were registered.
  - **Fix:**
    - Apply the caller's predicate to the layer hit, or limit the override to Babylon's pointer-selection pick.
    - Close the window with an insertFirst `onBeforeRender` observer.
    - On dispose, restore the original only if `scene.pickWithRay` is still our function.
    - Mention the patch in the CHANGELOG.
- [ ] **minor**: `_syncGamepadCover` (`tosi-b3d.ts:5976`) is a drifted copy of `_suppressGamepad` (`:1453`). It misses gamepads mounted as siblings and only sets `display`, so a hidden pad still reports input. Replace it with `this._suppressGamepad('in-scene-ui', covered)`. (unverified)
- [ ] **minor**: the fullscreen click listener is added again after every teardown and reconnect, because `_fullscreenWired` is reset while the button keeps its listener (`tosi-b3d.ts:6684`). The result is a double `requestFullscreen`/`exitFullscreen` and an unhandled rejection. Do not reset the flag (as `_scenePanelWired` already does), or keep a remover for the listener. (unverified)
- [ ] **minor**: with a custom `setupXr`, a flat modal stays on the flat camera's face frame when the player enters VR. Its observer is filtered to `rendering === cam`, so it does not update in the headset. The verifier found this while refuting scenario (b) of the modal re-presentation major. (verifier note, not independently verified)
- [ ] **minor (coverage)**: none of the layer, modal, claim, XR-pick or fullscreen behaviour has a test (`src/frame-panel.ts:96` and others). At minimum, add tests for:
  - a press on a ui-layer svg-plane is claimed;
  - two modals do not share a pose;
  - a modal survives NOT_IN_XR with `flatUi='dom'`;
  - `pickLayersFirst`, run against a NullEngine with a fake `onXRFrameObservable`.

  Several of these are already the checks for the Fix-before-the-tag items above. (unverified)
- [ ] **nit**: the `layer` attribute row in `src/b3d-panel.ts:111` still says "Flat only for now". Layers now apply in a headset too (modal, then ui, then the world). The row feeds `attributes.txt` and `llms.txt`, so the stale text spreads. (unverified)
- [ ] **nit**: `sceneToolbar` (`src/scene-toolbar.ts:59`) rebuilds its whole SVG on every hover and every mutation. Build it once per structural change, and toggle the highlight in place. (unverified)
