## Major

**1. Reciprocal fog blend can put `fogStart` above `fogEnd` (confirmed; correctness).** `src/atmosphere.ts:118`
- The new `reciprocal` mix falls back to a plain lerp when either value is 0 or less, and it is applied to start and end separately. A zero start is lerped toward 1e6 while the end barely moves.
- Measured: base `{start 0, end 4000}` with vacuum weight 0.05 gives start 50000, end 4210. `tosi-b3d.ts` writes both unclamped, so everything nearer than `end` renders as pure fog colour.
- Reached two ways: `b3dFog({ start: 0 })` in linear mode with atmosphere below about 0.75 (or a space climb); or the water's fog layer (`start: 0`) registered before the skybox while underwater with non-zero vacuum.
- It is a regression from this release. Land and Sky is unaffected (start 1000, sky registered first). The existing test only covers start 1000.
- The verifier corrected one example: vacuum 0.0001 is not reachable from a fresh scene because of the 0.002 update gate. The b3d-clouds `start: 0` path was not checked.
- Fix: keep start and end ordered inside the reciprocal branch (leave a zero start alone, or clamp start to end) and add tests for base start 0 and for a start-0 layer ahead of the reciprocal one.

## Minor

**Correctness**

2. **`biomeTemperature` keeps its name while its scale changes; an old `-1` is now -50 C with no warning (confirmed; correctness, docs and blast radius, deduped).** `src/b3d-terrain.ts:2035`
   - `-1` was the documented auto value and the old schema default, so a document saved with 0.8 defaults reloads as a frozen world and still validates.
   - Both sibling adopters set the attribute: manta-recon passes 0.7, 0.9, 0 and -0.6; ensemble's schema comment still says `-1` is the default. Neither can receive 0.9.0 without a deliberate bump (pinned `0.8.13` and `^0.8.13`).
   - The break is deliberate and documented in the CHANGELOG Breaking block and Migration.md item 1. The gap is the missing one-time warning for exactly `-1`.
   - Three comments are now wrong for temperature: `b3d-terrain.ts` near lines 501 and 2027, and `scene-schemas.ts:750`.
   - Not verified: that `shore="on"` then yields a frozen sea with a collision mesh.
3. **`shore="on"` falls back silently when the shader patch does not match, and the patch is page-global (confirmed; correctness and blast radius, deduped).** `src/b3d-water.ts:352`, `src/water-shore-shader.ts:151`
   - `registerShoreWater()` depends on six exact minified substrings of Babylon's water shader. On a mismatch it returns false and the water is built plain: no surf, no ice, no ice collision, `iceBearsAt` false everywhere, and no warning. No test references it.
   - All six match the installed Babylon today. Only the installed version was checked, not the `^9` range floor.
   - The patch rewrites the shader store once for the whole page. Any other `WaterMaterial` with vertex colours compiled later loses its tint and has its waves scaled by `1 - color.g`. The CHANGELOG scopes this to "the water mesh" only.
4. **The ice collision mesh covers dry land and is coarse far from the centre (unverified; correctness).** `src/b3d-water.ts:1228`
   - Reported at -30 C in Land and Sky: all 16641 vertices bear, 3801 on land, so an invisible colliding plane at sea level runs under the terrain. `iceBearsAt` also answers true on a beach.
   - Reported at -18 C: the mesh and `iceBearsAt` disagree on the outer grid, so a car or shell can fall through ice that is drawn solid. The biped uses the rule and is unaffected.
5. **Several runtime changes have no test that fails without them (unverified; correctness).** The water's own clock (writes Babylon privates `_lastTime` / `_lastDeltaTime`), skybox `alphaIndex` ordering, horizon tint and end-exact gate, `_updateIceMesh`, and the biped's use of `iceSide`.

**Efficiency**

6. **Pickable water goes from 2,048 to 18,432 triangles with shore on, 32,768 with `shoreFine` (confirmed).** `src/b3d-water.ts:352`
   - A ray that reaches sea level costs 0.035 ms on the old ground, 0.317 ms on the shore grid and 0.564 ms on the fine grid (verifier's own run).
   - The lens's "20 rounds is 10 ms/frame" example is overstated: a short swept segment that does not reach the water costs nothing. The recurring payers are long downward probes: aircraft ground probe, shadow decals, biped ground rays, pointer picks.
   - A second pickable mesh (the ice) sits on the same grid.
7. **The ice collision mesh is one unpartitioned sheet tested in full by every `moveWithCollisions` (confirmed).** `src/b3d-water.ts:383`
   - Cost is linear in triangles: about 9x and 15x a 2,048-triangle ground. The ratio is confirmed; the absolute per-call figure is not.
   - The mesh is enabled whenever any ice bears, not only when the sea is frozen solid. Opt-in.
8. **Shore data refresh is a synchronous hitch and the underside refresh has no throttle (unverified).** `src/b3d-water.ts:815`. Reported 4.5 ms per 32 m re-centre on desktop for the default grid; the ceiling recomputes every 4 m underwater and runs a `querySelector` plus a string key build every frame.
9. **Each biped runs a `querySelector`, a string build and a terrain sample per frame near shore water (unverified).** `src/b3d-biped.ts:2508`. `iceBearsAt` does the expensive lookups before its cheap early-out.
