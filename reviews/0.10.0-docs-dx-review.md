## Majors (all confirmed)

### M1. No install step or start-here path (docs + dx, merged)
- `README.md` never says `npm install tosijs-3d` or names the five required peers (`@babylonjs/core`, `gui`, `loaders`, `materials` ^9, `tosijs` ^1.9.2) or the optional `jolt-physics`. No published page does either.
- The second README code block (lines 69-89) has no heading and sits under the "Upgrading?" paragraph, so it reads as part of the migration note.
- The sample uses `./scene.glb` without saying the reader must supply it.
- After the README the nav goes Migration, Changelog, Demos, Core. There is no "first scene, then what" page.
- Caveat from verification: npm 7+ auto-installs peers, so the unresolved import mainly hits bun, pnpm, yarn-classic and importmap users.

### M2. The category tree misfiles and misorders pages (docs + dx, merged)
- UI has 39 children and Environment 37, each one flat list; together 76 of 182 pages.
- About 86 pages have no live demo. They are mostly pure models and internals, listed as siblings of the elements they serve.
- First pages are the wrong ones: Core runs b3d, b3d-elevator, library-mesh before b3d-loader; Vehicles opens with bone-mask and animation-layers before b3d-aircraft and b3d-biped.
- Misfiled: b3d-biped under Vehicles; lights split across Environment, Effects and UI; the HUD across Core, UI and Combat; buoyancy and swim-aim in Effects; b3d-physics and b3d-beacon in Utilities.
- Root order puts Migration and the 281 KB Changelog second and third.
- 7 or 8 of 12 landing pages are a heading plus a link list.
- About 156 of 182 titles are file slugs; `b3d-shadows` is the Sun page and `b3d-utils` is published as "Material Conventions".
- Checked and clean: every category toc matches its children, nothing is orphaned or duplicated.
- **Decision needed:** the two lenses proposed different target trees. The docs tree nests models under their element (18 groups, new Weather / Terrain / Water / Interaction categories). The dx tree keeps flat categories with a "Models and internals" group at order 900+ and splits UI into four. Both need only `parent`/`order` metadata edits plus landing-page prose. Pick one before starting.

### M3. 17 dead in-site links, and the pure models have no pages (docs + dx, merged)
- 17 link instances point at 11 targets with no page: fly-by-wire, guidance, ballistics, terrain-grid, perlin-noise, gradient-filter, gamepad, icon-data, MEDIUM-DESIGN, plus `[[MaskMode]]` in bone-mask (probably type notation, not a link).
- They ship: the built `b3d-aircraft` page has `href="?fly-by-wire.ts"` and `xr-gamepad` has `href="/gamepad/"`, a 404.
- Cause: exported modules with no `/*# */` block. That includes `b3d-primitives` (b3dBox / b3dSphere / b3dGround, used across the live demos), fly-by-wire, ballistics, guidance, warhead, destroyable, resource and perlin-noise.
- README's "Pure models, actually tested" highlight and the Combat landing page name these modules and can link to none.
- Pre-existing, not a 0.10 regression.
- Unverified side claim: about 20 design-doc names (COMBAT-DESIGN.md and others) are cited in published pages but are neither on the site nor in the tarball.

### M4. The world-contract example teaches what 0.10 says a driver must not do (docs)
- `src/world-contract.ts` lines 19-26: the page's only example spawns without `spec.id` and steers with `setIntent`. The same file's type comments and the 0.10 CHANGELOG say `spec.id` is mandatory and `setIntent` is legacy ("an entity given only an intent does not move").
- Headless examples on the world-contract and min-sim-conformance pages import from the `tosijs-3d` barrel. Reproduced: that throws `ReferenceError: HTMLElement is not defined`. The subpaths `tosijs-3d/world-store` and `tosijs-3d/min-sim-conformance` work.
- The min-sim-conformance "What it pins" list omits the choice primitive and the new `chooseOption` requirement.
- The world-store page does not say queries return copies or mention `liveState`; the world-view demo calls `getState()` twice per frame.

### M5. No automated tier mounts the live doc examples (coverage)
- Doc examples live in comments, so nothing type-checks them; `doc-examples.test.ts` is static regexes only.
- In this range: the b3d-hud demo shipped throwing from a 32 ms interval since a signature change (fixed 669979ea); two components logged a deprecation warning on every page (6ae5b7f9); three controls with removed `onX` names were caught at removal time (a near miss, not a shipped break).
- The only defence is RELEASING.md step 5a (a human drives every demo flat and in VR), which DECISIONS.md records as having been skipped before.
- Not a blocker **provided step 5a is actually walked for this tag.**

## Minors

**Confirmed**

- **m1. `handlerOf` warn-once key is the old name alone** (`src/handler-of.ts:57`; dryness + dx). `onEnter` is the removed name for both `inputField` (use `handleEnter`) and the trigger (use `whenEnter`). Reproduced: the second stale callback is dropped with no warning. Also the manipulator's message says "`handleChange` was removed in 0.10" with no component named, though `handleChange` is the correct name on every widget factory.
- **m2. Blast line of sight has two floor rules** (`src/b3d-warhead.ts:366`; dryness). `hasLos` still exempts any mesh named `ground` entirely, while the new `blastEye` lifts the origin 1 m over terrain. The new comment "a hill is still cover" is true for terrain and false for a mesh named `ground`. Also `new Set(destroyableMeshes)` is rebuilt per target, and `underDestroyable` is now a one-line alias. **Open question the dryness lens handed to correctness, with no answer in my input:** does the ray to a grounded target on terrain graze the surface and lose real blast damage?
- **m3. README claims the site contradicts** (`README.md:28`, `:63`, `:140`; docs). "Every page carries a live demo" (about half do); "147 doc pages" (197); "1000+ assertions in ~2s" (148,370 expects, about 14 s). `[b3d](?tosi-b3d.ts)` goes nowhere on npm and GitHub. The pre-rendered `docs/index.html` keeps `./Migration.md` and `./CHANGELOG.md`, which 404 for a crawler or no-JS reader.
- **m4. Wall-clock test flake** in `src/volumetric-surface.test.ts` (plausible; see "Test status").
