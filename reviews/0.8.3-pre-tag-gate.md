## Blockers (confirmed correctness; fix before tagging)

### B1: `_syncedClimate` is not reset in `sceneDispose`, so the climate and volcanic scale are silently lost after a re-parent
`src/b3d-terrain.ts:906` (verified)

`sceneDispose()` resets `_syncedSeaLevel` and `_syncedLapseRate` to NaN but leaves `_syncedClimate` alone. After any re-parent, `B3dChild.disconnectedCallback` runs `sceneDispose()`, and `sceneReady` then builds a fresh material. `attachBiomePlugin` gives that material a new plugin at its defaults (0.72 / 0.45 / 0.09). The climate key still matches the stale memo, so the three new attributes never reach the new plugin. A re-parent can come from moving an ancestor or from the doc system remounting.

In Land and Sky this means forest falls back to steppe, and the 0.02 plates fall back to 0.09 gravel. That is the value the user asked for, and nothing reports an error. This is also a gap in the memo pattern the 0.8.2 re-review (m1/m4) introduced: the copies were not kept in step.

**Fix:** add `this._syncedClimate = ''` next to the other two resets.
**Test:** in terrain-regenerate.test, set `biomeVolcanicScale = 0.02`, dispose and reattach, then assert `biomePlugin.params.volcanicScale === 0.02`. The assertion must read the consumer, per the AAR lesson.

### B2: `generationKey` stays the same after `regenerate()` changes only a landform or provinceField, so the cloud deck keeps orographic cloud over terrain that is gone
`src/b3d-terrain.ts:649` (verified)

`generationKey` returns `_genKey`, which is built only from attributes. The getter's doc says it changes on a `regenerate()`, but it does not when the change is to `landform`, `provinceField` or the profiles. `B3dCloudDeck._bakeWeather` (`src/b3d-cloud-deck.ts:1545-1571`) therefore skips the re-bake.

In Land and Sky, the 'volcano province' toggle calls `applyVolcano(false); terrain.regenerate()`. The camera is a FreeCamera that looks around in place, so the deck grid never moves. The orographic cloud dome over the removed 420 m cone stays indefinitely, and turning the toggle back on fails the same way.

**Fix:** add a monotonic shape counter that both `regenerate()` and `_rebuild` increment, and have `generationKey` return `${_genKey}#${counter}`. Keep `_genKey` as the internal dedupe key.
**Test:** `regenerate()` with a new landform changes `generationKey`.

## Completeness gaps
1. **Tree not clean:** `docs/version.json` is modified. It is a provenance stamp only (`git diff 81e81aeb 2b8e3822 -- src` is empty), but it must be resolved before tag or pack.
2. **Result not checked against the user's request:** "default the volcano scale to 0.02" was implemented as a **demo** default (`land-and-sky.ts` 0.025 → 0.02). The library auto default is still 0.09. That is probably the intended reading, since 0.09 suits a ~50 m cone and 0.02 a ~400 m one, but it has not been confirmed with the user. B1 would silently undo it after a remount.
3. **Removals in a patch** (`world-sim` subpath, the `/world-sim/` URL now pointing at the category page, `/sky/default_*.png`) were not reviewed as breaking changes or migrations. The CHANGELOG fix above covers the notes.
4. **GPU and XR paths have no pixel check:** the b3d-galaxy vertex-shader rewrite (855 lines) and the skybox changes (moon arc, sunless clock, starfieldTilt). A step-5a drive is not mandatory for a patch, but the galaxy shader is the riskiest runtime change. Recommend a flat screenshot through `haltija --private --app` before tagging.
5. **Schema check:** the new climate attributes are `num(-1, {minimum:-1, maximum:1})` in `scene-schemas`. Their range and meaning (1/m frequency for volcanicScale) were not checked against the attribute docs, because the docs/dx lens did not run.
6. **Re-baked star PNGs** (`static/sky/stars_*.png`): no check that the committed bytes come from the committed `SHIPPED_SKY` recipe.
