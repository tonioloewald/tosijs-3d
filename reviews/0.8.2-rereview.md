## 🟠 Confirmed majors (2)

### M2 — `biome` is the third member of the family this diff just straightened out: still a generation-key input, and the sync never disables the plugin

_Merged from `src/b3d-terrain.ts:1859` (blast-radius, major, verified) + `src/b3d-terrain.ts:1923` (correctness, minor, **unverified** — both facets were independently measured by the major's verifier, so the merged item is verified)._

- **(a) The toggle costs a world rebuild.** `a.biome` is still in `_generationKey()` (`src/b3d-terrain.ts:1859`), three lines under the comment (1831-1836) stating that only attributes determining the heightfield or tile grid belong there and "a change to `wireframe` or `debugColor` is a material tweak and must not cost a regeneration". Measured: flipping `biome` on→off costs 18 tile builds and marks 62 of 80 placed tiles stale (draining to the whole pool) — **the same cost class as the `grossScale` control (18/62/80)**, while `wireframe` costs 0 builds.
- **(b) The off direction is inert.** `_syncBiome()` (1912-1932) early-returns on `biomePlugin != null` and has no branch that disables; `attachBiomePlugin` sets `isEnabled = true` unconditionally and nothing in b3d-terrain ever writes `isEnabled = false`. Measured after `biome = 'off'` + render: `biomePlugin.isEnabled === true` and `pluginManager.getPlugin('Biome')` still present, so the chart colouring stays on the mesh while the attribute reads `'off'`. Worse than a plain one-way attribute: the spurious re-cut makes the failed off-toggle **look** like it worked.
- **Reachable and vended as a normal control:** `terrainEditor3d`'s BIOME group (`src/terrain-editor.ts:148,268`, applying live attribute writes), `scene-schemas.ts:489` (`choice('off', ['off','on'])`). The new test pins only the off→on half (`src/terrain-regenerate.test.ts`, "biome can flip on at runtime").

**Fix.** Drop `a.biome` from `_generationKey()`; in `_syncBiome()`, `if (isOff(a.biome) && this.biomePlugin) this.biomePlugin.isEnabled = false` (keep it attached for a cheap re-enable); extend the flip test with the off direction.

### M1 — the flagship demo still re-cuts the entire tile pool on every sea-level step, and both the commit message and the new code comment claim it no longer re-cuts any tiles

_`src/world-sim.ts:173` (blast-radius, major, verified)._

- `demo.seaLevel`'s observer writes the two biome dials and then calls `terrain.regenerate()` — the **unbounded** path (`clearPool()` + `update(pool.length)`, `src/b3d-terrain.ts:1954-1956`). Measured: the library spelling (write the attribute, then `render()`) → **0 builds**; the demo's spelling → **80 builds** on an 80-tile harness pool, and 68 of 68 placed on the demo's own config. A full drag of the 'sea level' slider at its own step (0.02, 51 steps) → **3468 re-cuts vs 0** with the library spelling.
- Only the **second** re-cut is gone (the write-before-`regenerate()` reorder this remediation made); the first is now provably unnecessary, because `biomeSeaLevel` is a live shader dial that feeds nothing in `_generationKey()`. `ff3f2662`'s "dragging the sea level no longer re-cuts any tiles" is true of the element's attribute path and false of the shipped page — and adopters copy this page, so the pattern propagates. The prior gate measured the same cost (52–93 re-cuts per step) and graded it major then; this is the residual half.
- **Do not simply strip `regenerate()` from all eight keys.** `wireframe` is applied **only** inside `_rebuild()` (`src/b3d-terrain.ts:1947`), so removing its `regenerate()` would silently kill the wireframe toggle too (measured: `wireframe = true` + render → 0 builds, `material.wireframe` stays false — the same dead-seam class as B1).

**Fix.** Split the observer loop: write `biomeSeaLevel` / `biomeLapseRate` / `water.y` in their own observer with **no** `regenerate()`, and call `regenerate()` only for genuine generation attributes (`seed`, `grossScale`, `detailScale`, `horizScale`, `grossAmplitude`, `detailAmplitude` — note `grossAmplitude` feeds the lapse rate, so its observer needs both halves). Give `wireframe` a `_syncBiome`-style live material sync. Then correct the claim in the comment/commit note to what is measured.
