## Blockers — fix before tagging (3)

### B1 · `canonicalize()` zeroes position AND rotation of EVERY top-level node under `__root__` — `src/model-transform.ts:91-100`

_correctness · verified (reproduced under NullEngine against `static/test-3.glb`)_

The new loop is gated only on `clone.name.includes('__root__')` and then iterates **every** direct `TransformNode` child:

```ts
const content = isGltfRoot
  ? clone.getChildren((n) => n instanceof BABYLON.TransformNode, true)
  : []
for (const child of content) {
  const t = child as BABYLON.TransformNode
  t.position.set(0, 0, 0)
  t.rotationQuaternion = BABYLON.Quaternion.Identity()
  t.rotation.set(0, 0, 0)
}
```

`test-3.glb`'s `__root__` has 8 top-level children at distinct poses; after `canonicalize` all 8 sit at the origin with identity quaternions. Reachable two ways: `b3dAircraft({ url })` (`src/b3d-aircraft.ts:1683` always hands `canonicalize` the glTF `__root__`; the `rootNodes.length !== 1` guard at :1668 is vestigial because glTF always yields a single `__root__`), and `canonicalize()` directly (`src/index.ts:745`). A multi-object export collapses into a pile; a `_centerOfGravity` Empty authored as a top-level _sibling_ has its offset zeroed, installing the pivot at the model origin — the inverse of the bug this change was written to fix. The surrounding comment and the contract line at `src/model-transform.ts:40` both say _the_ node, singular.

`src/model-frame.test.ts:108-121` loops over **all** children asserting `position ≈ 0`, so the suite pins the over-broad behaviour rather than catching it. Mitigation: no in-repo demo hits it (the library path renames the clone at `src/b3d-library.ts:536`, so `isGltfRoot` is false), and MIGRATION.md documents only the single-object case — so an adopter gets no warning.

**Fix:** zero only the single content node (skip the loop when `__root__` has more than one child, or take the target node explicitly). Update `model-frame.test.ts` to assert the single-node case and add a multi-node case asserting siblings keep relative placement.

### B2 · No `license` field and no LICENSE file — `package.json`

_blast-radius · verified_

`npm pack --dry-run` → 512 files, 1.0 MB packed, containing CHANGELOG.md, Migration.md, README.md and no LICENSE. `package.json` has no `license`, `description`, `homepage` or `bugs`. Siblings all declare one (`tosijs` BSD-3-CLAUSE, `tosijs-ui` MIT, `haltija` Apache-2.0), each with a LICENSE file.

This is **not a regression** — every published version since 0.2.1 has been unlicensed, and `npm view tosijs-3d license` is empty for the current `latest` (0.6.2). It is called a blocker because 0.7.0 is the first stable of the line and takes `latest`: absent a grant the package is all-rights-reserved, corporate SCA gates (Snyk/FOSSA/license-checker) flag an UNKNOWN-license direct dependency, and both real adopters consume it as a `file:` dep with nothing to point at. The package also ships BSD-attributed third-party code (`dist/mersenne-twister.js`) while granting nothing for itself.

**Fix:** one commit — add `"license"`, a root LICENSE file (npm packs it automatically), plus `description` / `homepage: https://3d.tosijs.net` / `bugs`.

### B3 · Adopter issue #31 — a `startPaused` scene renders Babylon's DEFAULT fog — unfixed at HEAD and unmentioned in the release notes

_ecosystem · verified_

`_update`'s paused branch (`src/tosi-b3d.ts:1465-1487`) returns before `_updateFog(dt)` (:1492), and `if (this.startPaused) this.pause('start')` (:2618) fires in the same synchronous `sceneReady` block _before_ the first tick — so on a scene that boots paused `_updateFog` has never run. `_updateFog` is the only writer of `fogColor`/`fogDensity`/`fogStart`/`fogEnd` in all of `src/`; `B3dFog.applyFog()` sets `fogMode` and stores `_fogBase`/`_fogNow` without touching the scene. Result is Babylon's constructor defaults byte-for-byte (`fogColor (0.2,0.2,0.3)`, `fogDensity 0.1`), exactly as the adopter measured.

Pause/`startPaused` is a headline 0.7.0 feature, and `startPaused` → press Start → `enterXrOnResume` is the documented VR entry path — so the broken frame carries the first impression. `grep '#31\|#32' CHANGELOG.md` returns nothing and there is no known-issues section, though the analogous #30 _is_ named at CHANGELOG.md:651.

Mitigating (why the fix can be either/or): with `b3d-fog`'s default `linear` mode the defaults are visually mild — the ~30 m whiteout needs `exp2` — and it self-heals on the first frame after resume.

**Fix (pick one):** prime the fog at scene-ready (call `_updateFog(0)` or apply `_fogNow` after `setFogBase`, before `pause('start')`), **or** add a **Known issues** block to the 0.7.0 CHANGELOG naming #31 and #32 with the one-line workaround. Either is minutes; shipping silence is what buys the second report.
