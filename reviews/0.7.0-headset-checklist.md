## 1. The riskiest change: `collidable()` rewrote every pick site

Four collision predicates were replaced by one shared, default-exclude
predicate. Two of the four were **never verified by the review** — they were
only reasoned about. A regression here looks like _shells passing through
targets_ or _turrets shooting through walls_.

- [x] **[NEW] Launcher demo — shells still hit.** ✅ PASSED (manual aim + AoE). Fire at the cubes. They should
      take damage and die exactly as before. **Fail:** rounds pass through, or
      detonate instantly at the muzzle.
- [x] **[NEW] Turret demo — LOS still blocked by real cover.** ✅ PASSED. (It
      only hits when smarter or faster — that is `smart` gating drop
      compensation, by design. Firing arcs filed in TODO.)
- [ ] ~~superseded~~ **Turret LOS** A turret should
      still refuse to shoot through solid scenery (`can-bear` / reticle colour
      changes). **Fail:** it happily shoots through a wall, or never fires at a
      target in the open.
- [x] **[NEW] Warhead demo — blast still blocked by real cover.** ✅ PASSED.
- [ ] **[CHANGED] Re-check the REWORKED warhead demo.** The wall now runs half
      the width with cubes on both sides, so ONE blast should kill three exposed
      far-side cubes and spare three sheltered ones at the same range.
- [ ] **[NEW] In VR, with the scene panel OPEN:** fire past/through the panel.
      Shells must ignore it entirely. **This is the fix** — previously a panel
      stopped shells, and a gaze-hidden (invisible) panel stopped them too.

## 2. The phantom-crash family (the big win — confirm it stayed fixed)

- [ ] **[RE] Aircraft demo, cockpit view, bank hard both ways.** No spurious
      crash. You confirmed this once; re-confirm because §1 touched the same
      file.
- [ ] **[NEW] Same, in b3d-clouds and b3d-terrain.** Cockpit + bank, near and
      far from terrain.
- [ ] **[NEW] Dive demo (`b3d-ambient` sea dive) — this could never work

- [ ] If anything here crashes: open **Perf Stats → "aircraft ground"** and read

## 3. Re-seat + freeze (new UI, only partly validated)

- [ ] **[RE] Volcano demo: re-seat and cancel** — you confirmed these.
- [ ] **[NEW] Re-seat in an aircraft CHASE view.** This did nothing before

      **Fail:** nothing happens until you toggle cockpit↔chase.
- [ ] **[NEW] Raise re-seat WHILE FLYING.** The aircraft must genuinely stop —

      Readable? Clearly distinct from the panel behind it?
- [ ] **[NEW] Right trigger commits, left cancels**, and the confirming pull
      does **not** fire your gun.
- [ ] Pause the scene yourself, then re-seat and finish. **You should still be
      paused afterwards** — the freeze must not clobber your pause.

## 4. Pause/resume in the standard panel [NEW]

> **[FIXED since this list was written]** the toggle rendered as a solid white
> box — `play`/`pause` were simply not in our generated icon set. Now added
> (bare glyphs, per your preference) and guarded by `icon-names.test.ts`.

Pause was a one-way door until now, so this control is brand new in both
presentations.

- [ ] **Flat:** gear panel → pause toggle stops the world; icon flips to `play`;
      pressing again resumes.
- [ ] **In VR:** same toggle in the panel's icon bar (next to Exit VR and
      Re-seat). **This is the only way to stop the world in a headset.**
- [ ] The icon shows the ACTION (`play` while paused). If it looks stale after
      pressing, that is a repaint bug — tell me.

## 4b. Clouds demo — two fixes since this list was written [NEW]

- [ ] **Land hard.** You should get a **DOWN panel with Respawn**, not a dead
      stick. It was not hanging: no `b3dDeath` meant `crash()` released input
      focus and left you holding nothing.
- [ ] **Does the aircraft cast a visible shadow now?** Cascaded shadows at 2048,
      because a 4000-unit ground put it in a coarse far cascade. **UNVERIFIED —
      reasoned, not seen.** If it is still missing, the caster side is already
      ruled out (aircraft and library meshes both register), so the next suspect
      is the receive side on `b3dGround`.
